# STAGE-009 · Установка темы через WordPress Admin с iPhone

Цель — вручную установить или обновить TOP-PARIKS Atelier на [тестовом сайте](https://top-pariks-test.freehosting.dev). Для установки, замены и активации требуется отдельное разрешение владельца на конкретный SHA. Обычный CI собирает и проверяет пакет. Загрузка в админке выполняется в Safari с выбором файла из приложения «Файлы». Workflow публикации и записи по FTPS запускать нельзя. Основной сайт и GitHub Secrets остаются вне процедуры.

## Скачать проверенный ZIP

1. В Safari войдите в GitHub и откройте **Actions → TOP-PARIKS CI**. Выберите завершившийся успешно запуск для согласованного коммита. Сверьте полный SHA коммита и убедитесь, что **PHP, JavaScript and Bash**, **WordPress theme and ZIP** и **WooCommerce smoke** завершились успешно. Для выпуска из `main` выбирайте запуск для согласованного SHA именно в `main`. [Запуски TOP-PARIKS CI](https://github.com/TonyGoalsMan1/top-pariks/actions/workflows/ci.yml)
2. Внизу страницы запуска, в разделе **Artifacts**, скачайте **top-pariks-theme**. Если раздел скрыт в Safari, в меню страницы выберите **Запросить настольный веб-сайт**. Откройте загрузки Safari или **Файлы → Обзор → Загрузки**. Нажмите внешний архив `top-pariks-theme.zip` один раз и откройте появившуюся папку. Для загрузки в WordPress сохраните внутренний **`top-pariks.zip`** в исходном виде. Запишите SHA и ссылку на запуск рядом с локальной копией.
3. Внутри `top-pariks.zip` должен быть один каталог `top-pariks/`, а в нём непосредственно `style.css`, `index.php`, `functions.php`, остальные PHP-шаблоны и `assets/`. CI собирает этот каталог из `theme/top-pariks/` через `git archive`, проверяет заголовки и обязательные файлы, тестирует ZIP и сравнивает распакованное дерево с исходниками и корневым ZIP репозитория. В качестве версии используйте поле `Version` в `style.css`. В исходном пакете STAGE-009 указаны версия 1.1.1, WordPress от 6.2 и PHP от 7.4. [Workflow CI](../.github/workflows/ci.yml) · [Заголовок темы](../theme/top-pariks/style.css)
4. При проверке на компьютере с чистой копией репозитория на согласованном SHA выполните `unzip -tq /путь/к/top-pariks.zip` и `python3 scripts/verify-theme-zip.py /путь/к/top-pariks.zip` из корня репозитория. Скрипт сверяет пути, типы записей и байты файлов. Для передачи файла между устройствами запишите SHA-256 внутреннего ZIP и сравните с полученной копией. GitHub указывает digest для внешнего артефакта. Если запуск не зелёный, SHA расходится, артефакт истёк или проверка архива провалилась, остановитесь. Для исчезнувшего артефакта нужен успешный штатный CI для того же согласованного SHA. [Проверка ZIP](../scripts/verify-theme-zip.py)

## Подготовить резервную копию и проверить стенд

1. В Safari откройте `https://top-pariks-test.freehosting.dev/wp-admin/`. Сверьте HTTPS, текущий хост и адреса WordPress и сайта в **Настройки → Общие** без сохранения изменений. В **Внешний вид → Темы** запишите имя, версию и каталог активной темы, состояние `top-pariks` (активна, установлена и неактивна, отсутствует) и наличие активной дочерней темы. Снимите исходные скриншоты главной, меню и магазина, запишите рабочие адреса назначенных страниц WooCommerce. Согласуйте окно, в котором никто параллельно не обновляет тему и настройки.
2. Проверьте возможность загрузки и восстановления. Нужны права на установку, обновление и активацию тем (при Multisite — соответствующий доступ в админку сети), доступная кнопка **Загрузить тему** и рабочий доступ к панели хостинга независимо от WordPress. В **Инструменты → Здоровье сайта → Информация** посмотрите версии WordPress и PHP, ограничения загрузки и права на файловую систему, если они показаны. Сверьте лимит на форме загрузки, лимиты провайдера на ZIP, на отдельные распакованные файлы, свободное место и квоту файлов. WordPress должен иметь возможность распаковать ZIP и записать каталог темы. [Загрузка тем в WordPress](https://wordpress.org/documentation/article/appearance-themes-screen/) · [Лимиты InfinityFree](https://forum.infinityfree.com/t/file-size-and-upload-limits/49308)
3. Если `top-pariks` установлен, выгрузите **весь текущий** `wp-content/themes/top-pariks/` из подтверждённого корня тестового сайта. Используйте штатное скачивание из File Manager хостинга, если оно доступно, или экспорт файлов из существующей системы резервного копирования. Если интерфейс позволяет скачать только отдельные файлы, сохраните все файлы с исходной структурой подпапок, включая скрытые. Сохраните копию локально в «Файлах» или в закрытом хранилище вне хостинга. Если активна дочерняя или другая тема, выгрузите и её полный каталог. При первичной установке зафиксируйте отсутствие `top-pariks` и убедитесь, что есть полная копия файлов прежней активной темы. Экспорт **Инструменты → Экспорт** выгружает контент WordPress и не содержит файлов тем. [Резервное копирование на InfinityFree](https://forum.infinityfree.com/t/how-to-backup-your-website/49304) · [Ограничения FTPS из STAGE-008](STAGE-008.md)
4. Подготовьте отдельный архив восстановления, например `top-pariks-before-YYYYMMDD.zip`. Если скачали дерево файлов, в «Файлах» можно зажать каталог `top-pariks` и выбрать **Сжать**. Распакуйте копию архива в отдельную локальную папку и проверьте, что на верхнем уровне только `top-pariks/`, а внутри сохранились все файлы, подпапки и версия из `style.css`. Сверьте список путей и размеры с оригиналом, при наличии хешей сверяйте и их. Сравните копию с кандидатом по путям и содержимому. Штатная замена очищает каталог назначения. Если на сервере есть локальные правки, дополнительные файлы или пропажи, которые кандидат не должен вносить, остановитесь до согласования и проверки пакета, сохраняющего нужные изменения. Зелёный CI подтверждает комплектность относительно Git. Он не видит файлов, добавленных на хостинге. [Обработка пакетов в WordPress](https://developer.wordpress.org/reference/classes/theme_upgrader/install/)
5. До начала операции подтвердите возврат через админку и запасной способ на случай её недоступности. При замене подтверждается восстановление старых файлов из панели или через поддержку, при смене темы — возможность вернуть прежнюю активную тему, даже если обычный вход в админку сломается. Отрепетируйте применимый сценарий на одноразовой копии WordPress с разрешённой загрузкой тем. Штатная Compose-песочница CI монтирует тему только для чтения и запрещает установку из админки. Для сохранения настроек темы и WooCommerce держите отдельную свежую резервную копию БД стенда, особенно перед сменой активной темы. Возврат БД может затереть изменения после снимка. Он требует отдельного согласования. [Конфигурация Compose](../compose.yaml)

**Стоп до установки.** Отсутствует разрешение, целевой домен расходится, нет полного читаемого бэкапа или проверенного пути восстановления, есть несогласованные отличия файлов, недостаточны права или лимиты, WooCommerce или ключевые страницы уже сломаны. Если активна дочерняя тема `top-pariks`, сначала подтвердите совместимость пары на изолированной копии и сохраните дочернюю тему активной.

## Установить или обновить с iPhone

1. После отдельного разрешения откройте **Внешний вид → Темы → Добавить новую тему → Загрузить тему**. Если элементы не видны, в Safari запросите настольную версию сайта. Нажмите **Выбрать файл → Обзор**, выберите внутренний `top-pariks.zip` в «Файлах» и ещё раз проверьте адрес стенда. Нажмите **Установить сейчас**. При первичной установке этот шаг уже пишет файлы на сервер.
2. **Первичная установка.** Если каталога `top-pariks` ранее не было, дождитесь сообщения об успешной установке. Затем нажмите **Активировать** для TOP-PARIKS Atelier и проверьте, что в списке тем появилась ожидаемая активная тема. Прежнюю тему оставьте установленной.
3. **Обновление.** Если каталог уже был, WordPress должен показать сравнение установленной и загруженной темы. Сверьте имя, версии и требования с проверенными архивами. Одинаковый номер версии возможен, поэтому идентифицируйте пакет по согласованному SHA и сверенным файлам. Нажмите **Заменить текущую загруженной** (формулировка зависит от версии и языка, на английском **Replace active with uploaded**). Дождитесь явного подтверждения успеха. Повторная активация уже активной темы не нужна. Если обновляли неактивную тему, её активация требует отдельного согласования в рамках операции.
4. Если видите форму FTP, предупреждение о совместимости, неожиданный экран, ошибку распаковки, прав, лимитов, TLS или тайм-аут, остановитесь. При ожидаемой замене отсутствие кнопки подтверждения также повод остановиться. Не вводите FTP-данные, не удаляйте тему и не повторяйте запрос вслепую. Запишите точный текст ошибки и время. В новой вкладке проверьте, открываются ли сайт и админка и какая тема сейчас активна. При повреждении или неполной замене переходите к откату.

## Проверить после установки

Проверьте результат сразу на стенде в двух вкладках Safari: админка и приватная вкладка для гостя. Если есть подозрение на старый CSS или JS, сравните в новой приватной вкладке и при необходимости сбросьте только кэш стенда штатным способом. Версия темы используется в URL CSS и JS и может остаться прежней.

| Проверка | Ожидаемый результат |
| --- | --- |
| Тема и файлы | В **Внешний вид → Темы** отображаются ожидаемая активная тема и версия. При дочерней теме проверьте отдельно версию родительской. По доступному чтению из панели хостинга сверьте установленные файлы `top-pariks` с ZIP, особенно если версия совпадает с прежней. |
| Главная и основные страницы | Главная `/`, «О компании» (`/about/`), «Доставка и оплата» (`/delivery/`) и «Контакты» (`/contacts/`) открываются на тестовом домене без ошибок и неожиданных редиректов. Проверьте меню, шапку, подвал, логотип, изображения, шрифты и ссылки по исходным скриншотам. Если адреса на стенде отличаются, используйте зафиксированные ранее рабочие ссылки. |
| WooCommerce | Плагин активен, каталог (`/shop/`), категория и карточка товара показывают фото, цену, наличие и варианты, если они есть. Добавьте тестовую позицию, проверьте счётчик в шапке, количество, итог и удаление в корзине (`/cart/`). С непустой корзиной откройте checkout (`/checkout/`) и проверьте видимость полей и итога. Откройте «Мой аккаунт» (`/my-account/`) и проверьте форму входа либо вход с существующей тестовой учётной записью. Используйте фактические адреса назначенных страниц. После проверки очистите тестовую корзину. |
| Safari на iPhone | В портретной и альбомной ориентациях меню открывается и закрывается, карточки и изображения помещаются в экран, горизонтальной прокрутки нет. Проверьте касания, читаемость кнопок и доступность полей при открытой клавиатуре на checkout. |

В рамках этой проверки остановитесь до отправки checkout. Не вводите реальные контактные или платёжные данные и не запускайте **Инструменты → Настройка витрины**. Сохраните ссылку на CI, SHA, версию, время и результаты проверок без учётных данных. Критическая ошибка PHP, недоступность админки, отсутствующие файлы, поломка главной, навигации, корзины или checkout, либо расхождение активной темы требуют остановки и отката.

## Откат

1. Если админка доступна и заменялся ранее установленный `top-pariks`, снова откройте **Внешний вид → Темы → Добавить новую тему → Загрузить тему**. Загрузите архив **из резервной копии перед операцией**. Сверьте имя, версию и каталог `top-pariks` и подтвердите замену. При откате на более старую версию WordPress может показать предупреждение. Сверьте, что указанная версия совпадает с резервной. При необходимости восстановите исходную активную тему через список тем.
2. Если `top-pariks` установили впервые и активировали, верните прежнюю активную тему кнопкой **Активировать**. Оставьте `top-pariks` установленной, но неактивной. Если первая установка прошла без активации, достаточно убедиться, что прежняя тема по-прежнему активна.
3. Если админка недоступна или замена резервным ZIP не проходит, используйте проверенный до установки запасной способ. При ошибке PHP можно воспользоваться ссылкой режима восстановления, если WordPress прислал её администратору стенда. При первой установке верните прежнюю активную тему в режиме восстановления или через согласованную поддержку без удаления новой темы. Если заменяли существующую тему и возврат через админку не удаётся, через панель хостинга или поддержку восстанавливайте только файлы `wp-content/themes/top-pariks/` подтверждённого стенда из сохранённой копии. Попросите сохранить снимок состояния после сбоя, если это возможно, и восстановить полное дерево из бэкапа со сверкой списка, чтобы лишние файлы кандидата не остались в рабочем каталоге. При невозможности выполнить точечное восстановление остановитесь. Не используйте FTPS для записи, не удаляйте тему через WordPress и не восстанавливайте БД поверх текущей без отдельного решения владельца.
4. После отката проверьте админку, исходную активную тему, версию и файлы, затем повторите проверки главной, страниц, мобильного меню и WooCommerce из таблицы. Запишите причину, способ восстановления и результат. Следующую установку начинайте после устранения причины и нового согласования.
