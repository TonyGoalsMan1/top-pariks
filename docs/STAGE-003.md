# STAGE-003 · Проверка FTPS и создание маркера стенда

Workflow **TOP-PARIKS staging FTPS marker** вручную проверяет FTPS и при явном подтверждении создаёт `/top-pariks-backups/staging-site.txt` с точным содержимым `https://top-pariks-test.freehosting.dev` без BOM и перевода строки. Для доступа используются существующие секреты окружения `staging-ftps`. Подключение использует explicit FTPS с проверкой сертификата, TLS 1.2 или выше и шифрованием канала данных.

## До запуска

- В панели InfinityFree выберите `top-pariks-test.freehosting.dev`. Сверьте **FTP Details** со значениями в окружении GitHub и подтвердите, что учётная запись и оба каталога принадлежат только этому стенду. FTPS проверяет структуру каталогов, а привязку домена к аккаунту подтверждает оператор.
- Проверьте, что начальный FTP-каталог — `/`, WordPress расположен в `/htdocs`, а `/top-pariks-backups` уже существует, доступен для записи и находится вне всех веб-корней, включая корни других доменов. В GitHub задайте эти два пути в `STAGING_FTPS_WP_ROOT` и `STAGING_FTPS_PRIVATE_DIR` соответственно. Настройка остальных секретов и защиты окружения описана в [STAGE-002B](STAGE-002B.md).
- Убедитесь, что сервер поддерживает полный листинг через `MLSD`. На время инициализации исключите параллельные изменения маркера через файловый менеджер, другие FTP-клиенты и внешнюю автоматизацию. FTP-команда `STOR` не поддерживает условие «создать только при отсутствии». В GitHub запуск уже синхронизирован с FTPS-публикацией стенда общей группой concurrency.

## Проверка и инициализация

1. После появления workflow в `main` откройте **Actions → TOP-PARIKS staging FTPS marker → Run workflow**. Выберите `main`, введите точный URL `https://top-pariks-test.freehosting.dev` и запустите режим `check`. Он только читает каталоги и существующий маркер.
2. Если в журнале указано `Staging marker verified.`, файл уже готов. Если журнал сообщает, что файл отсутствует в листинге, и условия выше выполнены, запустите `initialize` с тем же URL и введите в поле подтверждения `initialize top-pariks-test.freehosting.dev on an isolated account`.
3. Проверьте сообщение `Staging marker created and verified.`. Скрипт скачивает файл после записи и сравнивает байты. Повторный запуск `check` должен вывести `Staging marker verified.`. Повторный `initialize` при совпадении байтов также завершится без записи. Публикация темы запускается отдельным workflow.

При пропущенном job проверьте ветку, URL, режим и строку подтверждения. При ошибке подключения проверьте параметры в панели и GitHub, доступность TLS и `MLSD` с доверенным FTPS-клиентом. При ошибке записи или потере соединения сначала повторите `check`. Правильный маркер будет принят, а несовпадающее содержимое или неожиданный тип файла потребуют проверки оператором в панели. Скрипт завершится с ошибкой и сохранит существующий файл. Если тариф запрещает запись вне `htdocs`, остановите инициализацию и уточните возможности у провайдера.

Синтаксис обоих FTPS-скриптов проверяет CI без доступа к хостингу. Команда локальной проверки:

```sh
python3 -m py_compile scripts/staging-ftps.py scripts/staging-ftps-init.py
```
