# STAGE-002B · Доступ к тестовому хостингу

InfinityFree перечисляет `freehosting.dev` среди бесплатных поддоменов. На бесплатном тарифе SSH и SFTP недоступны, поэтому workflow с серверным WP-CLI на этом тарифе неприменим. Провайдер документирует FTP с TLS и публикует параметры в разделе **FTP Details**. Для конкретного аккаунта тариф, параметры FTPS и возможность безопасной замены каталога нужно подтвердить в панели или у поддержки. [Поддомены InfinityFree](https://forum.infinityfree.com/t/11-new-free-subdomain-options-now-available/118868), [SSH и FTPS](https://forum.infinityfree.com/t/how-can-we-use-ssh/79234), [FTP Details](https://forum.infinityfree.com/t/how-to-upload-files-with-ftp/49306)

## Что нужно получить от владельца

- Подтверждение, что аккаунт, файлы и база принадлежат только тестовому сайту, и что установлена и активна тема `top-pariks`. У владельца должен быть доступ к файловому менеджеру и админке WordPress.
- Из **FTP Details** нужны имя FTPS-сервера, порт, учётная запись и видимый в FTP абсолютный путь к тестовому WordPress. Уточните поддержку explicit TLS с проверяемым сертификатом для этого имени, защищённых пассивных соединений с GitHub Actions, `MLSD` и операций чтения, записи и переименования каталогов между путями. Проверьте квоту, лимиты размера файлов и число inode с учётом сохранённых копий.
- Нужен отдельный каталог, доступный FTPS для записи и размещённый на той же файловой системе, что и каталог темы. Его содержимое должно быть недоступно по HTTP, включая выполнение PHP. Предпочтителен путь вне всех веб-корней. Если тариф разрешает запись только внутри `htdocs`, владелец должен подтвердить поддерживаемую серверную блокировку всего каталога и проверить её на безвредном файле по всем привязанным доменам. Если закрытый каталог или перенос каталогов недоступен, этот workflow использовать нельзя. [Ограничение InfinityFree на запись](https://forum.infinityfree.com/t/missing-htdocs-folder-in-hosting-account/121324)
- Если в панели указан другой тариф с SSH, запросите SSH endpoint, порт, проверенный открытый ключ сервера, доступ по отдельному ключу и вывод `wp --info` из сессии этого пользователя. Остальные параметры и откат SSH описаны в [STAGE-002](STAGE-002.md).

## Настройка с iPhone

1. В Safari откройте панель хостинга и выберите именно сайт `top-pariks-test.freehosting.dev`. Сверьте **FTP Details**, путь WordPress и изоляцию аккаунта. В закрытом каталоге создайте файл `staging-site.txt` с единственной строкой `https://top-pariks-test.freehosting.dev`. Маркер подтверждает предварительную настройку каталога. Соответствие пути WordPress тестовому сайту проверяет владелец.
2. В Safari откройте репозиторий GitHub. При необходимости включите **Запросить настольный веб-сайт** в меню Safari. В **Settings → Environments** создайте `staging-ftps`, ограничьте публикацию веткой `main` и настройте обязательного ревьюера, если это позволяет тариф GitHub.
3. В самом окружении добавьте **Environment secrets** по таблице. Пароль вводится сразу в GitHub. Для автоматизации используйте отдельную учётную запись, ограниченную стендом, если тариф позволяет её создать.

| Secret | Значение |
| --- | --- |
| `STAGING_FTPS_HOST` | Имя из панели, совпадающее с именем в сертификате FTPS |
| `STAGING_FTPS_PORT` | Порт explicit FTPS из панели, обычно `21` |
| `STAGING_FTPS_USER` | Учётная запись тестового хостинга |
| `STAGING_FTPS_PASSWORD` | Пароль этой учётной записи |
| `STAGING_FTPS_WP_ROOT` | Абсолютный FTP-путь к тестовому WordPress без конечного слеша |
| `STAGING_FTPS_PRIVATE_DIR` | Абсолютный FTP-путь к закрытому каталогу с маркером без конечного слеша |

Предварительную проверку возможностей можно выполнить на пустых тестовых каталогах через FTPS-клиент или запросить у поддержки. Для проверки блокировки HTTP используйте браузер Safari. Настройка сама по себе публикацию не запускает.

## Публикация и восстановление

После отдельного разрешения владельца и появления workflow в `main` оператор сможет выбрать **Actions → TOP-PARIKS staging FTPS → Run workflow**, оставить ветку `main` и ввести `top-pariks-test.freehosting.dev`. Workflow ждёт успешного CI для выбранного SHA и сверяет ZIP с исходниками. FTPS требует TLS 1.2 или выше и проверяет сертификат системным хранилищем доверия. Пароль передаётся после установки TLS, для данных используется защищённый канал.

Скрипт считывает дерево прежней темы, загружает новую версию в закрытый каталог и проверяет набор файлов и SHA-256 повторным скачиванием. Затем переносит старое дерево целиком в `<закрытый каталог>/<FTPS backup ID>/previous`, проверяет его и переносит проверенную новую версию на место старой. После замены скрипт повторно сверяет файлы. Между двумя переименованиями возможен короткий перерыв. FTPS подтверждает состояние файлов. Активную тему, главную, каталог и корзину оператор сверяет отдельно в Safari после согласованного запуска. При этой операции база данных и активация темы не меняются.

При ошибке в ходе замены скрипт пробует восстановить прежний каталог через новую FTPS-сессию. При прерывании runner или сбое восстановления дождитесь завершения запуска, найдите ID из журнала или пару `run_id-run_attempt` и проверьте содержимое каталога этой попытки. Если там присутствует `previous`, переместите текущий `top-pariks`, если он есть, в закрытый каталог под отдельным именем и верните `previous` на место `wp-content/themes/top-pariks`. Если `previous` отсутствует, сначала выясните, успел ли скрипт начать замену или уже восстановил тему. Сохраните закрытые копии до завершения проверки, затем очищайте старые попытки через панель с учётом квоты.

## Проверки без доступа к сайту

PR запускает штатный CI. Отдельный workflow FTPS доступен только при ручном запуске с `main`. Для локальной проверки подготовьте ZIP командой `git archive --format=zip --output=/tmp/top-pariks.zip HEAD:theme top-pariks`, проверьте его через `python3 scripts/verify-theme-zip.py /tmp/top-pariks.zip` и используйте локальный FTPS-сервер с доверенным тестовым сертификатом и каталогами в отдельном временном корне.
