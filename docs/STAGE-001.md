## Сверка стенда без изменений

1. В Safari откройте подтверждённый тестовый домен и его `/wp-admin/`. Сверьте адрес в **Настройки → Общие** и имя окружения в панели хостинга. Если есть сомнения в том, какой сайт открыт, остановитесь.
2. В **Плагины → Установленные** найдите WooCommerce, запишите версию и статус (установлен, активен или отсутствует). В мультисайте проверьте также сетевую активацию. Если WooCommerce активен, посмотрите **WooCommerce → Статус** и назначение страниц в **Настройки → Дополнительно** и **Товары**. В **Товары → Все товары** проверьте фильтры, публикации и черновики.
3. В **Внешний вид → Темы** откройте сведения об активной теме. В **Инструменты → Здоровье сайта → Информация** сверьте версии WordPress/PHP, тему, родительскую тему и плагины, включая обязательные. При наличии доступа WP-CLI оператор может уточнить активные каталоги командами `wp option get stylesheet`, `wp option get template` и версии через `wp theme list`, `wp plugin list`, `wp core version`, задав путь и URL именно тестового сайта.
4. В приватной вкладке Safari откройте главную и URL магазина, затем сравните с теми же URL в авторизованной вкладке. Проверьте в WooCommerce **Настройки → Видимость сайта** режим Coming Soon и охват (весь сайт или магазин). Затем посмотрите активные и обязательные плагины обслуживания и их текущие настройки. В панели хостинга проверьте парковку домена, режим обслуживания, прокси/CDN и кеш. Если оператор проверяет HTTP-заголовки, используйте анонимный GET к тем же URL и сравните статус, редиректы, `Age` и признаки заглушки. Сопоставьте наблюдения с настройками, поскольку один заголовок или внешний вид страницы не определяют источник. На этапе аудита оставьте настройки и кеш в текущем состоянии.
5. Через файловый менеджер или SFTP с доступом на чтение скачайте только активный каталог темы (и родительскую тему, если есть). На компьютере распакуйте кандидат и выполните `diff -qr /путь/к/кандидату/top-pariks /путь/к/копии-темы`. При совпадающих именах и версиях используйте сравнение файлов как доказательство. Отдельно запишите различия конфигурации из админки. Если доступен только WordPress Admin, сверку содержимого выполняет оператор хостинга. Храните копии приватно.

## Сборка installable ZIP

В чистом checkout коммита PR выполните команды. Нужны Git, Bash, unzip и GNU coreutils.

```sh
./scripts/package-theme.sh /tmp/top-pariks.zip
unzip -Z1 /tmp/top-pariks.zip
unzip -tq /tmp/top-pariks.zip
sha256sum /tmp/top-pariks.zip
```

В корне архива должен быть один каталог `top-pariks/`, внутри — `style.css`, `index.php`, PHP-шаблоны и `assets/`. Скрипт проверяет заголовок темы, целостность обоих ZIP и совпадение распакованных файлов с исходником и корневым архивом. На iPhone проще открыть ветку PR на вкладке **Code**, перейти к файлу `top-pariks.zip` в ветке PR и скачать его кнопкой **Download raw file** в «Файлы». Если используется артефакт Actions `top-pariks-theme`, сначала распакуйте внешнюю обёртку в «Файлах» и выберите внутренний `top-pariks.zip`.

## Установка с iPhone после отдельного разрешения

1. Получите разрешение на запись в конкретное тестовое окружение. Нужны точный URL, учётная запись администратора WordPress и доступ к панели хостинга или оператору резервного копирования. Для сверки и аварийного восстановления нужен файловый менеджер/SFTP либо SSH, для БД — механизм восстановления хостинга. Передавайте доступы через менеджер секретов. В Git, PR и тикетах храните только обезличенные результаты.
2. Убедитесь, что тестовый WordPress использует отдельную БД, файлы и домен и защищён авторизацией хостинга или VPN. Заблокируйте исходящую почту и рабочие интеграции на стенде. Проверьте актуальный снимок БД и файлов, включая текущий каталог темы, плагины и загрузки. Зафиксируйте идентификатор снимка, место хранения, процедуру восстановления и ответственного. Подтвердите возможность восстановления в изолированном окружении. При отсутствии проверяемого снимка остановитесь.
3. В Safari откройте `/wp-admin/`. Если боковое меню скрыто, коснитесь ☰. Если кнопка загрузки недоступна из мобильного интерфейса, используйте **Меню страницы → Запросить настольный веб-сайт**, либо передайте установку оператору.
4. В **Плагины** проверьте WooCommerce. При необходимости установите официальный плагин и активируйте его на согласованном стенде. Пропустите подключения к внешним сервисам, настройку реальных оплат и установку рекомендованных расширений. В **WooCommerce → Настройки** проверьте адрес магазина, валюту, гостевой checkout, назначение магазина, корзины, оформления и аккаунта. Сохраните согласованный режим Coming Soon и ограничение доступа. Проверьте, что письма WooCommerce и исходящая почта заблокированы или направляются в почтовую ловушку, а шлюзы, вебхуки и синхронизация с внешними сервисами отключены.
5. В **Внешний вид → Темы → Добавить новую → Загрузить тему** выберите `top-pariks.zip` из «Файлов». Если WordPress предложит заменить существующий каталог `top-pariks`, сверьте показываемые версии и выполняйте замену только при отдельном разрешении на замену и наличии проверенного снимка. После активации подтвердите версию 1.1.1 и откройте главную. Проверьте меню и постоянные ссылки. При фатальной ошибке переходите к откату.
6. Скачайте [демо CSV](../fixtures/stage-001-demo-products.csv) в «Файлы». В **Товары → Все товары → Импорт** выберите CSV и оставьте выключенным «Обновить существующие товары». Проверьте сопоставление столбцов и запустите импорт. Ожидаются два черновика с префиксом `STAGE001-DEMO-`, названиями «[ДЕМО]» и условными ценами в валюте магазина. Изображения берутся из штатной заглушки WooCommerce. Для просмотра на закрытом стенде с разрешения опубликуйте только эти два товара на время проверки. Для повторного импорта сначала проверьте существование этих SKU.
7. В Safari пройдите главная → каталог → карточка → корзина → оформление. Проверьте названия, количество, итог и доступность элементов при повороте экрана. Используйте вымышленные данные и остановитесь до отправки заказа. Полный тест с отправкой выполняется в локальном Docker и создаёт только записи в тестовой БД.
8. Верните демотовары в черновики после проверки, запишите версии, точку восстановления и результаты. Ограничение доступа и Coming Soon сохраняйте в согласованном режиме. Отдельно зафиксируйте вопросы о реальных товарах, доставке, налогах, переводах и платёжном окружении.

## Откат с iPhone

1. Остановите проверку и оставьте ограничение доступа. Запишите URL, время, версию и симптомы. При ошибке загрузки темы используйте режим восстановления WordPress или свяжитесь с оператором хостинга.
2. Если предыдущая тема осталась отдельным каталогом, активируйте её в **Внешний вид → Темы**. Если был заменён тот же каталог, попросите оператора восстановить его из снимка. При необходимости восстановите БД и файлы из одной точки, учитывая изменения после снимка и согласовав восстановление с владельцем стенда.
3. Если полный откат БД не требуется, верните согласованные настройки страниц и видимости по записи из шага сверки. Найдите демотовары по `STAGE001-DEMO-` и оставьте их черновиками. Действия с плагинами согласуйте отдельно, особенно при миграции схемы WooCommerce. Проверьте блокировки почты и интеграций.
4. Откройте админку и главную в Safari, проверьте прежнюю версию темы, видимость в приватной вкладке и контрольные URL. Зафиксируйте результат. Если админка недоступна, оператор проверяет журнал ошибок и восстанавливает доступ через панель хостинга.

## Локальная проверка кандидата

Используйте новый проект Compose. Playwright ограничен локальным HTTP и проверяет маркер песочницы. Тест импорта рассчитан на свежую БД, а аккаунтный сценарий создаёт локального тестового пользователя.

```sh
export COMPOSE_PROJECT_NAME=top-pariks-stage001
docker compose config --quiet
./sandbox/start.sh
bash sandbox/woocommerce-smoke.sh
npm install --no-save --package-lock=false playwright-core@1.56.1
npx playwright-core install chromium
node sandbox/mobile-ux-smoke.cjs --account
node sandbox/mobile-ux-smoke.cjs
docker compose exec -T --user www-data wordpress php /tmp/top-pariks-wp-cli.phar \
  eval-file /opt/top-pariks/demo-catalog-smoke.php
docker compose down
```

CI также запускает `php -l`, `node --check`, `bash -n` и сборку ZIP. Playwright эмулирует размеры и ввод iPhone 13 в Chromium. Проверка физического iPhone в Safari остаётся пунктом приёмки на согласованном стенде.

### Фактический локальный прогон

- Синтаксис PHP, JavaScript и Bash, `docker compose config --quiet` и `git diff --check` прошли. Архив с одним каталогом `top-pariks/` прошёл `unzip -tq` и сравнение файлов с темой и корневым ZIP.
- HTTP smoke вернул `Test products, cart and offline checkout are available.`
- Chromium прошёл регистрацию, историю заказов и AJAX-счётчик. Гость оформил офлайн-заказы №15 (эмуляция iPhone 13) и №16 (desktop). Проверка ширин 320–1440 px прошла без горизонтальной прокрутки.
- На свежем проекте Compose импорт вернул `Success: Imported two marked virtual demo products as drafts.`
