## Заголовки и шаблоны

- `front-page.php` выдаёт один H1, заголовки секций H2 и названия карточек H3. Формулировку H1, общую вводную и заголовок подборки согласовать одновременно с дизайном.
- `woocommerce.php` делегирует вывод в `woocommerce_content()`. Каталог и категории дают по одному H1, товары в листинге — H2. На карточке один H1 с названием и H2 отзывов. Проверенные ответы ARCH-002 не содержали H4–H6. Глубину заголовков выбирают по структуре текста.
- `page.php` выводит H1 из заголовка и затем содержимое редактора. На контентных страницах начинать секции с H2. В `index.php` H1 выводится в цикле. При многоэлементном архиве записей это даёт несколько H1 по исходнику, текущий HTTP-прогон этот архив не охватывал. Для будущего блога нужен заголовок архива и H2 записей.
- В локальном стенде страницы корзины и аккаунта имеют по одному H1. Для 404 используется резервный H1 «Ничего не найдено». Редакционные страницы и их содержимое требуют инвентаризации.

## Адреса и редиректы

[HTTP-инвентарь стенда](verification.md) подтверждает только тестовые пути и два штатных временных перехода WooCommerce. Карта постоянных редиректов пока без записей, поскольку подтверждённого инвентаря production и согласованных смен URL нет.

Для production объединить актуальный sitemap, read-only экспорт опубликованных объектов WordPress и таксономий, crawl внутренних ссылок, выгрузки поисковых кабинетов и журналы. Сохранить исходный URL с хостом, код и конечный адрес, canonical, indexability, шаблон, ID, источник и дату наблюдения. После сверки подготовить колонки `старый URL | доказательство | новый URL | HTTP | основание | согласование | проверка`. Для согласованного постоянного переноса использовать 301 в один шаг на релевантный конечный 200. Проверить циклы, цепочки, дубль хоста и поведение query-параметров. Удалённая страница без эквивалента получает 404 или 410. Действующие URL и штатные переходы checkout не входят в миграцию.
